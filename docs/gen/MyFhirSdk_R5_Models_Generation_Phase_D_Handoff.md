## Phase C delivered state

The committed `Generated/R5/model-generation-manifest.json` is the provenance and artifact
baseline. It locks the official package SHA-256, primitive and model policy hashes, full generation
scope, deferred validation capabilities, and 831 generated model artifacts:

| Artifact group | Count | Owner |
| --- | ---: | --- |
| Complex datatypes and datatype components | 56 | `Generated/R5/Types` |
| Resources and Resource-owned Backbones | 773 | `Generated/R5/Resources` |
| Model metadata and validation composition | 2 | `Generated/R5/ModelMetadata` |

The SDK compiles these artifacts through the default project glob. The replaced handwritten
concrete Types, Resources, R5 metadata entry lists, MVP `datatype-preview` pipeline, preview type
set, and fallback type/resource mapping have been removed. `SimpleQuantity` remains handwritten
because it is an excluded constraint Profile, not an R5 specialization generated by Phase C.

## Supported generation operation

Run model generation into a staging directory:

```powershell
dotnet run --project CodeGen/MyFhirSdk.CodeGen.csproj -- `
  --mode model `
  --input Tests/CodeGen/Fixtures/FhirPackages/R5/hl7.fhir.r5.core-5.0.0.tgz `
  --output <staging-root> `
  --fhir-version 5.0.0 `
  --package-id hl7.fhir.r5.core `
  --package-version 5.0.0
```

The CLI requires an explicit `--mode primitive` or `--mode model`. Copy the staged
`Generated/R5/{Types,Resources,ModelMetadata}` and manifest only after review. Verify committed
output with:

```powershell
dotnet test Tests/CodeGen/MyFhirSdk.CodeGen.Tests.csproj -c Release `
  --filter FullyQualifiedName~CommittedModelGenerationTests
dotnet test MyFhirSdk.sln -c Release
git diff --check
```

## Retained bootstrap ownership

| Types | Owner | Reason retained | Exit criterion |
| --- | --- | --- | --- |
| `Base`, `Element`, `BackboneElement`, `BackboneType`, `DataType`, `Resource`, `DomainResource` | Runtime foundation | Shared inheritance and execution contracts currently live in the SDK assembly | An approved assembly-boundary ADR and compatibility suite allow Models to depend on Runtime without a cycle |
| `PrimitiveType<T>` | Runtime primitive foundation | Generated primitive wrappers require the generic value/metadata contract | A versioned standalone Runtime contract is published and consumed by CodeGen/Models |
| `Extension`, `Meta`, `Narrative` | R5 versioned bootstrap | Base model properties and extension/open-type behavior require these declarations before generated model composition is available | Ownership migration preserves public API, JSON behavior, metadata coverage, and introduces no duplicate declaration |
| `FhirObject`, `IFhirExtensionValue` | Runtime contract | Model root and extension-value marker are execution contracts rather than generated R5 declarations | Retain permanently unless superseded by an approved Runtime contract revision |
| `SimpleQuantity` | Handwritten profile model | Constraint Profile is outside Phase C specialization generation scope | A Profile-generation phase owns constraint declarations and passes the C0 public API snapshot |

## Phase D debt register

| Item | Owner | Current reason | Exit criterion |
| --- | --- | --- | --- |
| CodeGen references `MyFhirSdk.csproj` | Phase D dependency seam | CodeGen needs Runtime contracts while Runtime and generated Models share one assembly | CodeGen references a minimal versioned Runtime contract/package and has no dependency on generated concrete Types or Resources |
| Roslyn uses `typeof(DataType).Assembly.Location` | Phase D compilation service | Full-batch compilation validates against the current Runtime-compatible SDK assembly | Runtime reference is supplied explicitly and works from an installed tool without repository build output |
| External bootstrap CLR lookup | Phase D dependency seam | Metadata IR verifies only policy-approved external bootstrap identities against the current SDK assembly | Lookup consumes the explicit Runtime reference/contract; it must never scan an assembly for concrete model inventory |
| Repository-root locator and protected output assumptions | Phase D CLI host | Current defaults resolve policies and safety boundaries from repository/executable layout | Installed tool accepts explicit/package-owned inputs and safely generates outside a cloned repository |
| Tool packaging | Phase D packaging | CodeGen is currently an executable project, not a .NET tool package | `PackAsTool`, command/package/version metadata, local manifest install/restore/update, and clean-machine smoke tests pass |
| Version compatibility | Phase D release policy | Current baseline is CodeGen `1.0.0`, package/FHIR `5.0.0`, primitive policy `1.1.0`, Runtime `phase-a-v1+c4-primitives-v1`, .NET 9 | Compatibility checks reject unsupported combinations with deterministic diagnostics and the supported matrix is documented |

## Architecture gates inherited by Phase D

- model mapping comes only from validated primitive policy and definition inventory views;
- no production preview set, static model whitelist, fallback resource factory, or assembly-scan
  inventory may return;
- generated metadata is the only default R5 provider inventory;
- CodeGen may use approved Runtime/bootstrap contracts but not handwritten concrete
  `MyFhirSdk.Types` or `MyFhirSdk.Resources` declarations to complete generation;
- full-batch output remains byte-deterministic and committed-generation drift remains empty.

Phase D must preserve these gates while changing packaging and dependency delivery.
